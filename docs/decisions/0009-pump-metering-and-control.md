# ADR-0009 · 泵计量、控制信号与失电默认态

- 状态：已采纳
- 日期：2026-08-06
- 来源：硬件评审 v2 · N-1 / N-2

## 背景

[ADR-0004](0004-power-domains.md) 把主泵移到 **220V AC** 后，产生两个漏洞：

1. **泵电流监测失去实现路径**：INA219/226 是直流分流式（26V/36V 上限），测不了 220V AC 泵，且板上根本无泵功率路径。而"泵电流突增=堵 / 归零=停"这条链贯穿 [§6.5](../handbook/06-power.md)、[§16.4 预测维护](../handbook/16-testing.md)、[§18.8 风险表](../handbook/18-risk-and-safety.md) 与 **MVP-4 验收「泵流上 HA、拔泵手机响」**。
2. **泵控制信号的电气形式与失电默认态未定义**：ADR-0004 只说"出一路信号给外部继电器/SSR"，[§8.7](../handbook/08-actuators.md) 对主泵失电默认态写"视策略而定"，一直空白。

## 决定

**泵计量**：
- **PZEM-004T v3**（AC 电能表，UART/Modbus，内部隔离，直接出 V/I/P/kWh；ESPHome 原生 `pzemac`）**+ YF-S201 流量**，互为冗余（电流=早期堵塞信号，流量=直接信号）。底板留一个 **UART header（2 pin + 电源）**。
- **INA226 保留但改测 12V 母线 / 电池 / 12V 负载支路**（打氧泵/阀/风扇/灯），不再测主泵。

**泵控制信号**：
- **光耦隔离 + 高有效 + 3.3/5V 跳线可选**。
- ⚠️ **禁止低有效**（上电 GPIO 浮空 → 继电器误吸合 → 泵自启，经典坑）。

**主泵失电默认 = ON**（继电器 **NC 触点**，MCU 无信号即通）：
- 理由：泵停的"水位/淹水"风险已由物理溢流 + 集水桶兜底；但泵停的**循环损失**无物理兜底——生化滤床停流数小时开始掉菌、夏季 DO 跌。这正是铁律一"物理负责不死"**覆盖不到**的部分。
- **前提（三者都在电路层，不依赖软件）**：
  1. 溢流改**无虹吸重力堰**（见 [P1-8]，避免"泵一直转 + 虹吸断"导致的持续溢流）；
  2. 加一路**独立硬件高水位浮球，直接断泵（不经 MCU）**，作淹水兜底；
  3. 配合加分功能 #4 **手动强制开关**。

## 后果

- 底板加 UART header + 泵控制走隔离输出级（NC 默认通）。
- `node-tank01.yaml`：INA 改测 12V 母线、泵计量另走 PZEM/流量、注释改正。
- `functional-spec` A 类拆分「电流/功率」为「12V 母线电流=INA226」+「泵功率/电流=PZEM」+「流量=YF-S201」。
- [§8.7](../handbook/08-actuators.md) 定稿主泵失电默认 = ON（NC）+ 硬件高水位断泵。
