# 第 1 章 · 前言与如何使用本手册

## 1.1 这是什么项目

`aquaponics-lab` 是一个**家庭智能鱼菜共生生态实验平台**。它表面是"阳台养鱼种菜"，本质是一个**开源、模块化、可持续迭代的家庭 SCADA（数据采集与监控）系统**——鱼和菜是"负载"，真正被工程化的是围绕它的**感知、控制、供电、数据与自动化**系统。

它不是一个"产品"，而是一个**平台**：核心闭环稳定后，可以不断往上叠新模块（新传感器、新执行器、视觉、AI、离网供电、闭合物质循环），永远有下一个可玩的迭代。

## 1.2 为什么要写这本手册

项目从一个人的娱乐项目，演进为**有实验室背书、要做展示 demo、且有协作者参与**的正式开源项目。当两个人（甚至更多人）并行开发时，最大的风险不是技术难度，而是**沟通熵**：

- 两个人对"这个接口是 5V 还是 3.3V"理解不同 → 烧板子。
- 硬件改了针脚定义没同步 → 固件对不上。
- 谁负责哪块不清楚 → 要么重复劳动，要么都以为对方在做。

这本手册的目的，就是把**共识固化下来**：架构怎么分层、每个模块的原理与边界、模块之间的**接口契约**、谁负责什么、怎么协作提交。有了它，每个人都能独立、放心地在自己的分支上推进，最后一拼就通。

## 1.3 读者对象

| 想复刻的人 | 第 2、3 章 → 第 4–12 章按需 → [`../02-build/`](../02-build/) 施工 + [`../20-bom`](20-bom.md) 备料 |

## 1.4 文档约定

- **语言**：中文为主，关键术语给英文；术语见 [第 22 章 术语表](22-glossary.md)。
- **单位**：SI 单位；温度 °C，体积 L，流量 L/h，扬程 m，压力 kPa。
- **符号**：⭐ 重点；⚠️ 安全/易错点；🔧 动手要点；📐 公式；🔬 原理。
- **稳定性标注**：每章开头标"稳定 / 演进中 / 草稿"，避免把草稿当定论。
- **引用**：手册引用而非复制 living docs；改了接口/架构要同步更新本书并写 ADR。

## 1.5 与仓库其他文档的关系

```
本手册 (docs/handbook/)  ── 稳定的"宪法"：为什么、是什么、怎么对接
   │ 引用
   ├─ docs/decisions/  ADR   ── 一条条可追溯的决策
   ├─ docs/02-build/         ── 会变的施工步骤（按 MVP）
   ├─ docs/04-operations/    ── 运维手册
   ├─ firmware/ hardware/    ── 真正跑的代码与设计
   └─ docs/03-bom/           ── 采购
```

> 一句话：**手册讲"道"，living docs 讲"术"。** 道稳，术变。
