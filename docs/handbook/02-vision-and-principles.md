# 第 2 章 · 愿景、目标与设计原则

> 稳定。本章是整个项目的"价值观"，其它所有决策都要能回溯到这里。

## 2.1 愿景 Vision

> 打造一个**可复刻、可持续迭代**的家庭智能生态实验平台，把鱼菜共生变成一个**看得见、测得到、玩得动**的开源工程系统——优先工程美感、可玩性与长期迭代能力，而非产量。

## 2.2 目标 Goals（可衡量）

1. **稳定闭环**：核心水循环 + 生物过滤能长期（月级）稳定运行，鱼健康存活。
2. **数据化**：关键量（温度、水质、流量、能量）全部可实时观测 + 长期记录。
3. **自动化**：常规运维（喂食、补水、降温、告警）无需人工干预。
4. **可复刻**：他人照手册 + BOM + 接线图 + 配置，能从零复现一套。
5. **模块化**：新增/替换一个模块不影响其余；支持长期升级。
6. **离网就绪**：能以太阳能 + 电池为主供电，市电仅作兜底。

## 2.3 非目标 Non-Goals（明确不做）

- ❌ 不追求高产量 / 商业化产出。
- ❌ 不追求"全自动零维护"的封闭黑盒——**可玩、可改、可 hack** 比"省心"更重要。
- ❌ 不做需要专业施工/破坏房屋结构的重型改造。
- ❌ 初期不追求极致低功耗或工业级可靠性（先能跑、能玩，再逐步硬化）。

## 2.4 三条设计铁律 Iron Rules

这三条凌驾于一切炫技之上，任何设计冲突时以此裁决。

### 铁律一 · 物理失效安全优先 ⭐

> **绝不让"电子系统正常"成为鱼存活的前提。**

断电、断网、固件崩溃、水泵烧毁——系统都必须靠**重力与物理结构**撑住数小时到一天。做法：钟形虹吸、恒水位溢流、集水桶兜底、备用打氧。电子系统负责"更好"，物理结构负责"不死"。这既是工程底线，也是对活体的**伦理底线**。

### 铁律二 · 一切可热插拔

> **加一个模块 = 插上即用；拔一个模块 = 其余照跑。**

- 机械：统一角钢 + 3D 打印卡扣。
- 电气：统一航空插头（GX12/16）、统一 12V DC 母线。
- 软件：统一 MQTT 主题命名空间，节点自动被 Home Assistant 发现。

这条铁律的技术保证就是[第 13 章 接口契约]。

### 铁律三 · 数据即乐趣

> **把生态变成可观测、可回放、可分享的数据流。**

氮循环曲线、水质趋势、太阳能发电、鱼的活跃度……记录下来、画出来、报出来。数据不是负担，是这个"实验室"最好玩的部分，也是它区别于"一口鱼缸"的根本。

## 2.5 设计价值观 Design Values

| 价值观 | 含义 | 体现 |
|---|---|---|
| **工业风** | 明管、透明管段、塑料桶、3D 打印件、可见结构 | 看得见的水流与线路 |
| **低成本** | 闲鱼 + DIY + 复用 | 弱层板货架、二手缸、捡的过滤桶 |
| **模块化** | 松耦合、可替换 | 一模块一 ESP32、快接管路 |
| **可复刻** | 别人能照做 | BOM + 接线图 + 配置全开源 |
| **可迭代** | 永远有下一步 | 分阶段 MVP + 升级路线 |

## 2.6 成功的样子（1 年后）

- 阳台上一台工业风的"生态实验室"稳定运行，多口透明缸、可见管路、状态屏。
- 手机上能看实时仪表盘，异常自动推送。
- Grafana 里有几个月的水质/能量历史曲线。
- GitHub 上有人 star、有人提 issue、甚至有人复刻。
- 你和协作者都能对着它讲清楚"每一部分的原理和为什么这么设计"。
