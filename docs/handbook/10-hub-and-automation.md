# 第 10 章 · 中枢、网络与自动化（M7）

> 演进中。负责人：系统/软件。中枢是系统的"大脑皮层"——做跨模块决策。

## 10.1 职责与边界

- **职责**：汇聚所有节点数据，做跨模块自动化、告警、可视化入口；下发指令。
- **接口**：MQTT 主题约定、实体命名（见 [第 13 章](13-interfaces.md)）。

## 10.2 MQTT：消息总线 🔬

**MQTT** 是轻量发布/订阅协议，是本项目的"神经"。

- **模型**：发布者把消息发到**主题（topic）**，订阅者订阅主题收消息，二者解耦（不用互相知道）。
- **Broker**：中间人（如 Mosquitto，跑在树莓派）。
- **主题命名空间** ⭐：统一 `aqua/<node>/<metric>`，如 `aqua/tank01/water_temp`。通配 `aqua/#` 订阅全部。
- **QoS**：0（至多一次）/1（至少一次）/2（恰好一次）。传感遥测多用 0/1；命令用 1。
- **保留消息(retained) + LWT**：可用保留消息存最新状态；**遗嘱消息(Last Will)** 让节点掉线时 Broker 自动发"离线" → 支撑失联告警。

## 10.3 Home Assistant：编排中枢 ⭐

- 通过 MQTT 发现或显式配置接入所有实体。
- 提供仪表盘、历史、自动化引擎、通知（手机推送）。
- 配置组织（见 [`home-assistant/`](../../home-assistant/)）：用 `packages/` 按功能拆分，敏感信息进 HA 的 `secrets.yaml`。

## 10.4 控制理论基础 🔬

自动化不是"if 温度高就开风扇"这么简单，要避免**震荡**与**误触发**。

### 10.4.1 迟滞控制（Hysteresis）

单阈值会在临界点频繁开关（抖动）。用**双阈值**：温度 > 32°C 开风扇，< 30°C 才关。中间 2°C 死区避免频繁切换。**大多数本项目回路用迟滞即可。**

### 10.4.2 PID（进阶）

对需要精确稳定的量（如恒温），可用 PID：
$$ u(t) = K_p e(t) + K_i \int e\,dt + K_d \frac{de}{dt} $$
- $K_p$ 比例（当前误差）、$K_i$ 积分（消除稳态误差）、$K_d$ 微分（抑制超调）。
- 本项目多数场合迟滞已够；加药/恒温可探索 PID。

### 10.4.3 安全联锁与限幅 ⚠️

- **前提校验**：加药前必须有近期有效 pH 读数。
- **限幅 + 冷却**：单次加药量上限 + 两次间隔冷却，防坏值导致过量。
- **看门狗式告警**：数据超范围/长时间无更新 → 判故障。

## 10.5 关键自动化清单

| 自动化 | 逻辑 | 优先级 |
|---|---|---|
| **失效告警** | 泵停/流量 0/缺水/温度异常/节点离线 → 手机推送 | ⭐ 最高（不可省） |
| 高温降温级联 | >30°C 开风扇 → >32°C 加遮阳+打氧 → >34°C 提醒人工 | 高 |
| 太阳能优先调度 | 电足跑重负载；电低只保命 | 中 |
| 定时喂食 | RTC/时间触发 + 摄像头验证 | 中 |
| 光周期 | 植物灯按日程 + 光照传感 | 中 |
| pH 加药闭环 | pH 越界 → 蠕动泵限量加药（带联锁） | 中（高风险，谨慎） |
| 天气联动 | 拉广州天气：热浪预降温、台风提醒 | 低 |
| 自动补水 | 低水位 → 电磁阀补水（带超时保护） | 低 |

## 10.6 Node-RED（可选，复杂流程）

对可视化流程/复杂条件，可用 Node-RED 补充 HA 的自动化，适合快速搭原型逻辑。

## 10.7 网络与可靠性

- 节点与中枢同一局域网；Broker、HA 跑在树莓派。
- 断网降级：节点本地保命；恢复自动重连。
- 时间同步：SNTP + 各节点 RTC 兜底。
