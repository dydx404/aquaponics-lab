# 第 13 章 · 接口契约 Interface Contracts ⭐

> 稳定（改动需 ADR + 双方确认）。**这是全书最重要的一章**：只要接口契约稳定，两个人就能在各自分支上独立开发、互不阻塞，最后一拼就通。

## 13.1 为什么接口契约是并行开发的关键

模块之间只通过**明确定义的接口**耦合。硬件负责人只要保证"我出线的针脚定义、电平、数据主题符合契约"，软件负责人就能在不看硬件实现的情况下写好对接。**改接口 = 改公共契约 = 必须 ADR + 通知对方**；改模块内部实现则自由。

接口分四类：**电气、机械、软件、数据**。

## 13.2 电气接口 ⚡

### 13.2.1 电源母线

| 项 | 规范 |
|---|---|
| 主母线 | 12V DC，正/负极色标：红=+12V，黑=GND |
| 逻辑电源 | 5V（DC-DC 降压），3.3V 由 ESP32 板载 LDO |
| 逻辑电平 | **3.3V**（ESP32）。5V 器件对接需电平转换 |
| 每支路 | 独立保险；大电流支路加开关器件 |
| 共地 | 所有模块**共地(GND)**，星形接地优先 |

### 13.2.2 连接器标准（航空插头）

- 入水/模块间统一 **GX12 / GX16 航空插头**，防水可插拔。
- **针脚定义必须登记**（示例，最终以附录为准）：

| 插头 | 针 | 信号 | 说明 |
|---|---|---|---|
| GX16-4（传感） | 1 | +5V | 传感器供电 |
| | 2 | GND | 共地 |
| | 3 | SDA / 信号 | I²C 或模拟/数字 |
| | 4 | SCL / 信号 | I²C 时钟 |
| GX12-2（12V 负载） | 1 | +12V | 负载正 |
| | 2 | GND | 负载负 |

> ⚠️ **母线极性、连接器针脚定义一旦公布即为契约**。硬件按此出线，软件/整合按此接入。变更走 ADR。

### 13.2.3 I²C 地址分配

多器件共总线靠地址区分，维护唯一地址表（见 [第 21 章附录](21-appendix-pinouts.md)）。新增器件先查表、防冲突。

### 13.2.4 信号约定

- 数字输入默认上拉、低有效需注明。
- 模拟量注明量程与对应物理范围。
- 感性负载驱动**必须含续流二极管**（硬件契约，见 [第 8 章](08-actuators.md)）。

## 13.3 机械接口 📐

| 项 | 规范 |
|---|---|
| 安装基准 | 传感/执行装于 3D 打印底座，卡扣统一卡角钢/管路 |
| 打印公差 | 配合孔 +0.2~0.4 mm；螺纹用热熔螺母 M3 |
| 管路 | 主管 25 mm；排水/溢流 32–40 mm；快接/球阀便于拆装 |
| 开孔 | 塑料平壁=水箱接头；圆桶=Uniseal（尺寸表见附录）|
| 玻璃缸 | **不钻孔**，缸口/背挂溢流 |
| 承重 | 缸长 ≤40 cm 上层板；≥50 cm 落地；放水层板垫木板 |

## 13.4 软件接口 💻

### 13.4.1 MQTT 主题模式 ⭐

**统一命名空间**：

```
aqua/<node>/<metric>
```

- `<node>`：`tank01` / `power` / `grow` / `vision` …（不含 `node-` 前缀，前缀在设备名里）。
- `<metric>`：`water_temp` / `water_level` / `pump_current` / `battery_v` …（snake_case）。
- 命令主题：`aqua/<node>/<actuator>/set`。
- 状态/遗嘱：`aqua/<node>/status`（online/offline，用 LWT）。

示例：
```
aqua/tank01/water_temp      27.4
aqua/tank01/low_water       ON
aqua/power/battery_v        12.6
aqua/grow/light/set         ON
```

### 13.4.2 命名与配置约定

- 节点设备名：`node-<function><index>`。
- 文件/目录：kebab-case。
- 密钥：一律 `!secret`；`secrets.yaml` 进 `.gitignore`（公开仓库红线）。

## 13.5 数据接口（单位与量程）📊

统一单位与量程，避免"你以为 mV 我以为 V"这类事故：

| 量 | 单位 | 合理范围 | 备注 |
|---|---|---|---|
| 水温 | °C | 0–40 | 超范围判故障 |
| pH | — | 0–14（常用 5–9） | 需温补/标定 |
| EC | µS/cm 或 mS/cm | 视植物 | 温补到 25°C |
| DO | mg/L | 0–15 | 温度/盐度补偿 |
| ORP | mV | −500~+800 | — |
| 浊度 | NTU | 0–1000 | — |
| 水位 | cm 或 % | 0–缸高 | 另有浮球布尔兜底 |
| 流量 | L/min | 0–20 | 脉冲换算 |
| 电流 | A | 视支路 | INA/ACS |
| 电压 | V | 0–15（12V 系统） | — |

## 13.6 接口变更流程 ⚠️

1. 提出变更 → 开 Issue。
2. 写/更新 **ADR**（[docs/decisions](../decisions/)）说明原因与影响。
3. **双方（硬件 + 软件）确认**。
4. 同步更新本章与 [第 21 章附录](21-appendix-pinouts.md)。
5. 相关分支据新契约调整。

> 口诀：**内部实现随便改，公共接口要开会。**
